## 自走テストハーネス設計

エージェントが人間の介入なしに各イテレーションのAUTO部分を判定するための検証基盤。

- **非干渉性の目的**: OS APIを一律に禁止するのではなく、同じコンピュータ上のユーザー作業を妨げない。OS入力、フォーカス/前面ウィンドウ、可視ウィンドウ操作、実デスクトップキャプチャ、実スピーカー・マイクを使用せず、ヘッドレス/オフスクリーン実行、プロセス内API、隔離した仮想デバイス、固定パスへ出力する観測物を使う: ...
- **手動確認の自動化禁止**: 前面化、ウィンドウ操作、入力注入、デスクトップキャプチャでHUMAN項目を代行しない: ...
- **統一エントリポイント**:
  - `setup`: 依存導入・初期化（例: `...`）
  - `run`: 成果物の起動（例: `...`）
  - `verify`: 全自動検証の実行（例: `...`）— **exit 0 = AUTO部分の完了**
- **判定方式**: exit code / 構造化ログ（JSONL）/ スナップショット / HTTP レスポンス / **エージェントによる画像のマルチモーダル直接確認** のうち採用するもの
- **マルチモーダル確認の運用**: 隔離したテストプロセスが画像を固定パスへ出力し、Codexが「期待される表示状態」と一致するか判定する。デスクトップ、他アプリ、ユーザーの作業内容を含むキャプチャは使用しない。判定基準は各イテレーションで明記する
- **非干渉メタデータ**: UI/E2Eでは`window_created`、`window_visible`、`focus_requested`、`os_input_events`、`os_input_injected`、`capture_source`等を記録し、欠落または違反をfailにする
- **再現性の確保**: 乱数シード固定、時刻のモック、外部依存（ネットワーク・DB・LLM など）のスタブ化方針
- **観測物の保存先**: ログ・スクリーンショット・スナップショットの固定パス
- **失敗時のデバッグ手順**: どのファイルを見れば原因が分かるか
- **権限昇格時の判断**: WindowServer、Accessibility、画面収録、入力監視等の権限を要求する前に非干渉性を確認し、禁止操作が必要ならAUTOを停止してHUMANとして残す

## イテレーション計画

- `HUMAN`: ユーザーが結果を明示的に報告するまで未完了とする。エージェントはOS操作で代行しない。
- `AUTO`: エージェントが非干渉な`verify`と成果物で判定する。
- `verify`のexit 0はAUTO部分の完了であり、イテレーション全体の完了にはタスク、AUTO、HUMANの完了が必要である。
